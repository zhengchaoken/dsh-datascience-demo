# 数据与 Python 执行范式

## 数据路径

- 示例数据用相对路径（如 `src/data/ecommerce/ecommerce.db`），不写绝对路径。
- 工作目录默认取插件/服务进程目录，可用环境变量（如 `DSD_WORKSPACE`）固定，避免宿主改 cwd 后找不到数据。

## 查询

- 只放行合法的 `SELECT`，默认 `select * from <table> limit 100`，最大 1000 行。
- 只读连接 + `query_only`，防止写操作。
- 参数化传值；表名/字段名做白名单，不直接拼进 SQL。
- 返回结构保持稳定（列、列类型、行数、耗时），前端不因驱动变化而改。

## Python 脚本调用

- 优先子进程而不是把 Python 内嵌进进程：脚本零改动、崩溃隔离、可超时杀掉。
- 脚本路径用**白名单**，不接受任意路径；参数用 argv 数组。
- 每次执行记录：脚本名、参数摘要、退出码、耗时。
- 输出按行流式转发（SSE 或轮询快照），不要让界面干等。
- 超时与取消必须实现，训练类脚本要能整组杀掉。

## 长任务

- 任务队列 + 并发上限（默认 2~4），超出排队而不是直接打满机器。
- 每个任务有状态：排队、运行、成功、失败、取消，并有错误信息与日志尾部。
- 同一个任务重复提交要幂等，已在运行就直接返回当前状态。

## 报告与产物

- 绘图脚本必须遵守字体顺序（先 set_style 再设中文字体），否则中文乱码。
- 报告图片相对路径；生成脚本支持 `--out-dir`。
- 报告中的锚点标签全部删除，避免显示原始 HTML。
- 产物目录与文档保持同级，方便面板直接读取。
- 面向用户的报告不写实现说明、不写「由脚本生成」这类字样。

## 性能

- Node 只做编排，把计算放进 Python 子进程；不要在 Node 里跑重计算。
- `node:sqlite` 是同步 API，并发场景要放 worker 线程或独立进程。
- 大结果集分页或游标，不要一次拉全量。
- 静态资源与 API 分离后，静态交给反向代理或 CDN，后端只处理 API。

## 数据集变更

- 生成脚本要可复现：固定随机种子、固定锚定日期，保证同一份代码产出字节一致的库。
- 表结构变更后按生效清单执行：停服务 → 删库文件 → 重启 → 重新生成。
