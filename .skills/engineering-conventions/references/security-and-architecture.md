# 安全边界与架构范式

## 认知前提

- **前后端分离不是安全边界**。它带来的是部署独立、攻击面收敛、可加网关，不带来「攻破了也看不到东西」。
- 真正决定泄露范围的是：鉴权有没有、权限有多大、凭证放在哪。
- **换语言也不产生安全边界**。Rust / Go 主要降低内存类问题与依赖投毒概率；「接口无鉴权」「执行层是 root」这类问题换语言原样存在。
- 顺序永远是：先鉴权与最小权限，再谈拆分与网关。

## 危险接口清单（必须收口）

以下能力一旦可被外部触发，等价于把服务器交给对方：

| 能力 | 风险 | 收口方式 |
|---|---|---|
| 触发系统包管理器安装 | 以 root 装任意包 | 仅本地回环可调 + 显式确认 + 包名白名单 |
| 任意 SQL 查询 | 可读全库（含未来放进去的凭证） | 只读连接 + SQL 白名单 + 强制行数上限 |
| 执行脚本 / 命令 | 任意代码执行 | 脚本白名单 + argv 数组 + 非 root + 超时 |
| 读写任意文件 | 路径穿越 | 规范化路径 + 前缀校验 + 拒绝 `..` |
| 返回用户 HTML | 同源 XSS | 强制 `text/plain` 或用沙箱 iframe，禁止原样 `text/html` |
| 用户指定外部源地址 | 供应链 / SSRF | 协议限制 + 域名白名单 |

## 外部命令

- `spawn` 一律传数组，禁止 `shell: true` + 字符串拼接。
- 需要 shell 时，可执行文件必须是常量白名单，参数不得包含用户输入。
- 安装类操作要记录审计日志（谁、何时、装了什么）。

## 数据库

- 只读连接 + `PRAGMA query_only`。
- 参数化查询；需要动态 SQL 时用解析器校验，只放行 `SELECT`。
- 强制 `LIMIT`（默认 100，最大 1000），大结果集用分页或游标。
- 注意 `node:sqlite` 是同步 API，会阻塞事件循环；并发查询要放 `worker_threads` 或独立进程。

## 凭证与配置

| 内容 | 放哪 | 原因 |
|---|---|---|
| 普通配置（端口、源地址、并发上限） | 配置文件 + 环境变量覆盖 | 可版本化、可灰度 |
| 连接串、口令、API Key | 系统钥匙串 / Vault / KMS | 备份、日志、导出、SQL 查询都可能顺手泄露 |
| 凭证引用 | 业务库只存 ID | **业务库一旦有 SQL 查询接口，凭证进库就等于开后门** |

- 凭证接口只写不回显，读接口最多返回名称、更新时间、掩码。
- 内存里用最短生命周期持有，注入子进程后即销毁，日志统一脱敏。
- 凭证绝不打进前端产物，前端只拿引用。

## 执行层隔离

- Python / bash / Docker 操作与 API 进程分离：独立进程或容器、非 root、只读挂载、出站白名单。
- 超时必须能杀掉整个进程组，不能只杀父进程。
- 任务要有队列：并发上限、队列长度上限、超时、取消。
- 隔离比换语言更重要。

## 部署形态

同一份代码，三种形态，靠开关切换：

| 形态 | 进程 | 适用 |
|---|---|---|
| 单体 | 1（后端同时托管静态） | demo、单机、插件形态 |
| 分离 + 反代 | 2（静态服务 + API） | 生产、需同源、独立扩容 |
| 分离 + CDN | 2（CDN + API） | 大流量、跨地域 |

- 开发期用 dev server 代理 `/api` 到后端，避免开 CORS。
- 生产期优先同源（反代聚合），浏览器看到的始终是一个域名。
- 必须跨域时才开 CORS 白名单 + credentials；凭证放 HttpOnly Cookie 或 Bearer，不放 localStorage。
- 前端 API 基地址由环境变量注入，默认同源路径，不硬编码端口。

## 网关

- 何时加：需要统一登录、多租户、公网暴露、限流审计时。早期不要加，会拖慢迭代。
- 只做四件事：TLS 终止、身份与权限、流量治理（限流/超时/重试）、路由与静态资源。
- 业务判断留在服务内部。
- 网关校验通过后注入签名头，后端拒绝无该头的直连，防止绕过网关。
- `X-Request-Id` 与租户标识全链路透传，便于审计。

## 插件形态的特殊性

需要注册路由与工具的宿主插件，前端不是独立服务，天生是「一个进程」。所以插件形态保持单体，独立 Web 形态才做分离，同一份代码支持两种形态，不要为了「安全」强行拆插件。
