# TypeScript / Node 编码范式

## 类型与依赖

- `tsconfig` 开 `strict: true`，不用 `any` 糊过去；确实未知用 `unknown` 再收窄。
- 依赖尽量少。能用标准库就不引三方包；引入前先算清打包体积与维护成本。
- 外部副作用（时间、随机、文件、网络、子进程）通过接口注入，便于测试。
- 前后端共享的类型放 `shared/` 单一来源，不要两边各写一份。

## 模块体系

- ESM 与 CJS 不混用。项目是 ESM 就全链路 `import`，是 CJS 就全链路 `require`。
- 不要靠改文件后缀（`.cjs`）来「修好」模块冲突，那会制造入口漂移。
- ESM 里取目录：

```ts
const __filename = fileURLToPath(import.meta.url)
const __dirname = path.dirname(__filename)
```

  不要写 `const __dirname = __dirname || ...` 这种自引用兜底。
- Windows 下 `node_modules/.bin` 下的可执行文件需要 `.cmd` 后缀。把「可执行文件选择」收敛到一处平台判断，不要散落多处。

## 子进程

- 一律传 argv 数组，不拼字符串。除非万不得已不用 `shell: true`。
- 需要 shell 特性（管道、通配）时，把可执行文件与参数都限制为常量白名单，绝不拼接用户输入。
- 必须设超时，超时后杀**整个进程组**（Windows 用 Job Object，类 Unix 用进程组），否则训练脚本的孙进程会残留。
- 输出按行切分并收集最近若干行，失败时把尾部输出拼进错误消息：

```ts
reject(new Error(`命令退出码 ${code}：${file}（${tail}）`))
```

- 长输出要截断（例如日志上限 800 行），避免内存被撑大。

## 错误处理

- 不用空 `catch`。捕获后要么转换、要么记录、要么重抛。
- 对外错误信息要能定位：命令、参数、退出码、尾部输出。
- 后台任务（如安装）不要抛出未捕获异常，用状态机记录 `idle / running / succeeded / failed` 和错误字段，供界面读取。

## 文件与路径

- 路径统一用 `node:path` 的 `join/resolve`，不用字符串拼接。
- 读取用户可控路径前做规范化与穿越校验，拒绝 `..` 与绝对路径越界。
- 写文件前先确认父目录存在。

## 日志

- 结构化、分步：每一阶段一条，形如「阶段名：结果」，便于用户定位卡在哪。
- 不打印凭证与完整请求体；必要时脱敏。
- 同一任务内的日志带时间前缀，便于对照。

## 测试

- 每个能力自带可运行示例与最小测试，不依赖外部服务才能跑。
- 跨能力依赖只指向公共 `shared/`，不要让 A 示例 import B 示例。
- 测试要覆盖边界：空值、超长、跨平台路径、失败分支。

## 代码风格

- 注释写「为什么」，不写「是什么」。明显代码不加注释。
- 不给未改动的代码补注释、补类型、补文档字符串。
- 删除确定无用的代码，不留「已废弃」注释和兼容垫片。
