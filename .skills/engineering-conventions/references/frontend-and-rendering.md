# 前端界面与渲染范式

## 图片与资源路径

- Markdown 报告里的图片**一律相对路径**，禁止绝对路径。绝对路径换机器就裂图。
- 生成脚本支持 `--out-dir`，默认输出到脚本所在目录，保证文档与图片同目录同步。
- 报告被嵌入面板时，资源路径以报告文件所在目录为基准解析。

## 中文图表字体

seaborn 的 `sns.set_style()` 会重置字体配置，先设的中文字体失效，导致方框乱码。

正确顺序：先 `sns.set_style(...)`，再设置中文字体（如 `plt.rcParams['font.sans-serif'] = ['Noto Sans CJK SC', ...]`），并处理负号显示。所有绘图脚本（L1/L3/L4/L5 与探查脚本）都要遵守这个顺序。

## Markdown 渲染的坑

- **以 `|` 开头的非表格行**会让某些解析器死循环，最终 OOM 崩渲染进程。写内容时避免这种行；写解析器时必须对「分隔行/非表格行」做容错与最大循环次数保护。
- **`<a id="sec-x"></a>` 锚点残留**在渲染器里不解析，会直接显示成原始 HTML。生成报告时不要输出锚点标签，已有的要删干净。
- 表格分隔行必须严格是 `| --- |` 形态，否则按普通文本处理。

## 导航与路由

- 顶部面包屑每一级都要能点击跳转。
- 没有独立页面的层级，跳转到它的**第一个子菜单页面**，不要给死链。
- 用 hash 路由时，要同步 `history`，保证浏览器前进/后退可用；`hashchange` 与 `popstate` 都要处理。
- 刷新后要保持当前页，不能总是回到首页。

## 面板内打开 HTML 报告

- 用 iframe 指向报告文件，而不是把 HTML 拼进 React 树（避免样式污染与脚本冲突）。
- iframe 要有明确的宽高与滚动策略，避免高度塌陷。
- 报告内含图表时，确保图片相对路径与 iframe 的基准地址一致。

## 界面文案与信息密度

- 面向最终用户：只讲业务含义，不讲实现方式（不出现「通过 API 拉取」「由 Node 服务渲染」）。
- 一个板块只回答一个问题，不要把校对说明、备选方案、开发备注塞进去。
- 数字带单位，比例标清口径；估算值要标注为估算。
- 中英混排时统一空格与标点风格，不要一半中文冒号一半英文冒号。

## 验证方式

- 改完界面必须真实打开一次，确认布局、滚动、跳转、图片都正常。
- 截图空白或快照超时，不代表页面有问题，改用 DOM/坐标核算补充验证，并如实说明「未通过截图确认视觉细节」。
