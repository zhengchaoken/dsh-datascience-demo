# 1. 数据与真值标签

数据中被刻意注入两类异常：
1. **批发型异常**（约 1.2% 订单）：单行数量 30~200 件；
2. **价格异常**（约 0.5% 订单）：成交单价 = 正常价 × 10。

由于真实注入标记不可见，用规则**近似构造真值标签**：
- `quantity >= 30`（批发阈值）；
- `unit_price > 3 × 所属二级类目价格带上沿`（价格带上沿取该类目标价的 95 分位）。
订单级标签：订单内任一明细行命中即为异常订单。

| 指标              |    数值 |
|:----------------|------:|
| 明细行总数           | 36907 |
| 命中异常的明细行        |   307 |
| 其中 quantity>=30 |   238 |
| 其中 单价超价格带3倍     |    69 |
| 异常订单数（去重）       |   307 |

**说明：** 该规则是注入模式的近似还原——价格异常的判定依赖类目价格带口径，个别「10 倍于低价商品」的注入单若未超过类目价格带 3 倍会被漏标，因此后文的 precision/recall 是对模型效果的近似评估。

# 3. IsolationForest

**Python 代码：**

```python
iso = IsolationForest(n_estimators=300, contamination=0.02, random_state=42)
pred = (iso.fit_predict(X_scaled) == -1).astype(int)
# 与近似真值比较
precision = TP / (TP + FP); recall = TP / (TP + FN)
```

| 指标        |       数值 |

**解释：** IsolationForest 通过随机切分孤立样本，异常点更容易被孤立。contamination=0.02 略高于真实异常率（约 1.3%），用召回换覆盖。

# 4. LOF（局部离群因子）

| 指标        |       数值 |
|:----------|---------:|
| TP        |  34.0000 |
| FP        | 329.0000 |
| FN        | 258.0000 |
| Precision |   0.0937 |
| Recall    |   0.1164 |
| F1        |   0.1038 |

**解释：** LOF 比较样本与其 k 近邻的局部密度。批发单（数量极大）处于稀疏区域，容易被 LOF 捕获；但 LOF 对全局稀疏异常（如孤立的 10 倍单价）在标准化空间中可能不如 IsolationForest 稳定。

# 5. 模型对比与可视化

| 模型              |   Precision |   Recall |     F1 |
|:----------------|------------:|---------:|-------:|
| IsolationForest |      0.7135 |   0.8870 | 0.7908 |
| LOF             |      0.0937 |   0.1164 | 0.1038 |

**解释：** Precision 回答「报警的订单中有多少是真异常」，决定运营审核成本；Recall 回答「真异常抓住了多少」，决定风险敞口。业务上风控场景偏 Recall，审核资源紧张时偏 Precision。

# 6. 结论与建议

1. 两类注入异常在特征空间中形态不同：批发单靠 `total_qty/max_qty` 捕获，价格异常单靠 `max_price` 捕获，特征工程比算法选择更关键。
2. IsolationForest 与 LOF 在本任务上互补：前者全局切分、对极端值敏感；后者基于局部密度。生产上可两者取并集提高召回。
3. 真值标签是规则近似，评估数字有偏差；若有真实标注（如风控审核记录），应以其为准并可升级为有监督模型。
